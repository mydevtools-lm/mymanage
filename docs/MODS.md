# Mods לעבודה על הפרויקט — תוכנית

Mod הוא תוסף קטן ל‑Claude Code: חלונית, שורת מצב, פס מעל שורת ההקלדה, פקודה, או
״שומר״ שבודק פעולה לפני שהיא רצה. המסמך הזה מתכנן את ה‑mods לעבודה על Lior
Management — כל אחד נולד מתקלה או מכלל שכבר קיימים, לא מרעיון כללי.

- **עודכן:** 12.10.2026
- **מצב:** טיוטה — מחכה להחלטות מ1–מ4 בסוף
- **קיים היום:** `desktop-sprints` (חלונית הספרינטים), בתיקייה של שיחה אחת בלבד

---

## 1. הבעיה הראשונה: mods נעלמים בין שיחות

Mod שנבנה בשיחה נשמר ב‑`~/.claude/dev-mods/<מזהה השיחה>/` ונטען רק בה. שיחה חדשה
לא רואה אותו. כך כבר קרה עם `git-band`, `hebrew-rules` ו‑`sprint-flow` — הם
נבנו בשיחה אחרת, ואין אותם כאן.

**הפתרון:** שתי תיקיות קבועות, ושורה אחת בהגדרות.

| תיקייה | מה בה | למה שם |
|---|---|---|
| `tools/mods/` במאגר | mods של הפרויקט הזה (`lm-*`) | גרסאות עם הקוד, עוברים עם ענף, נבדקים בשער |
| `~/.claude/mods/` | mods אישיים לכל פרויקט | שפה, תאריכים, גיט — לא שייכים למאגר ציבורי |

`~/.claude/settings.json` מקבל ב‑`env` את `CLAUDE_CODE_PLUGIN_DIRS` עם שתי התיקיות,
ואת `CLAUDE_CODE_PLUGIN_DIR_WATCH=1` כדי ששמירה של קובץ תטען אותו מחדש גם באפליקציית
הדסקטופ. זה שינוי הגדרות קבוע — רק באישורך (מ4).

## 3. ה‑mods

### `lm-sprints` — הספרינטים והשער · בפרויקט

ההמשך של `desktop-sprints`, שכבר עובד.

- **חלונית:** ד0–ד6 מתוך `docs/DESKTOP.md`, הספרינט הנוכחי וסעיפיו, ענף ושינויים
- **״עבודה: דN״** — שולח לשיחה את הספרינט עם הסעיפים הפתוחים (קיים)
- **שער לפי שינוי** (חדש): `vitest related` על הקבצים ששונו מול `main`, ו‑`cargo test`
  רק כשנגעו ב‑`src-tauri/`. דקה במקום חמש
- **שער מלא** (חדש): lint, ‏tsc, ‏vitest, ‏cargo, ‏build ו‑e2e — רץ ברקע, החלונית
  מראה התקדמות, וההודעה בסוף אומרת אם מותר למזג
- **הלוח ב‑claude.ai:** לפי מ2 — או שהחלונית מחליפה אותו, או שהיא מזכירה בסוף כל
  ספרינט לעדכן אותו

**מוכן כאשר:** ספרינט מתחיל, מתקדם ונסגר בלי לפתוח את המסמך ובלי להקליד פקודת בדיקה.

### `lm-guard` — שומר · בפרויקט

בודק כל פעולה של Claude לפני שהיא רצה. חוסם רק מה שגורם נזק; על השאר מזהיר.

| מצב | מה הוא עושה |
|---|---|
| פקודת shell עם גרש הפוך בתוך מחרוזת במירכאות כפולות | חוסם, ומציע לכתוב את הקובץ בכלי העריכה |
| עריכה של `src/` בזמן ש‑`next build`, ‏`test:e2e` או `tauri build` רצים ברקע | חוסם עד שהריצה נגמרת |
| הפעלה שנייה של `app.exe` או `tauri dev`, או `npm run dev` כשפורט 3000 תפוס | חוסם, ואומר מה כבר רץ |
| `git push --force`, ‏`git reset --hard`, ‏`git clean -f` | חוסם — אתה מריץ אותם בעצמך אם צריך |
| `git add` של `.env*` או של `data/` | חוסם |
| קומיט של עבודת ספרינט ישירות על `main` | מזהיר |

**מוכן כאשר:** כל אחת מהתקלות בטבלה בסעיף 2 (שורות 3–5) נחסמת בבדיקה של ה‑mod.

### `lm-desktop` — אפליקציית הדסקטופ · בפרויקט

- **חלונית:** האם האפליקציה רצה, גודל המתקין האחרון, זמן פתיחה וזיכרון מהמדידה האחרונה
- **כפתורים:** בנייה (`npm run tauri build`, ברקע), הפעלה, בדיקת עשן
  (`scripts/desktop-smoke.mjs`), סגירה
- שומר על מופע אחד: ״הפעלה״ כשהאפליקציה כבר רצה מביא אותה קדימה

**מוכן כאשר:** הבנייה, ההרצה ובדיקת העשן של ד3–ד4 נעשות מהחלונית.

### אישיים — ב‑`~/.claude/mods/`

- **`git-band`** (קיים): שורה מעל ההקלדה — ענף, קבצים שלא נשמרו, קומיטים שלא נדחפו
- **`hebrew-rules`** (קיים): מכניס את כללי השפה לכל שיחה, ומסמן תשובה שגלשה לאנגלית
- **`israel-time`** (חדש): כלי ש‑Claude קורא לו — תאריך, יום בשבוע ושעה בישראל,
  כולל מעבר לשעון חורף. מחליף את `date` שמחזיר UTC

## 4. סדר העבודה

```
מ0 קבע מקום → מ1 lm-guard → מ2 lm-sprints → מ3 lm-desktop → מ4 אישיים
     S             S              S              S              S
```

1. **מ0 — מקום קבוע:** `tools/mods/`, `~/.claude/mods/`, ההגדרה מסעיף 1; `desktop-sprints`
   עובר ל‑`tools/mods/lm-sprints`. מוכן כאשר שיחה חדשה טוענת אותו בלי לבנות כלום.
2. **מ1 — `lm-guard` קודם:** הוא מונע את התקלות שכבר קרו, והוא הקטן מכולם.
3. **מ2 — `lm-sprints`:** שער לפי שינוי ושער מלא ברקע.
4. **מ3 — `lm-desktop`:** לפני ד3 (מעטפת) ו‑ד4 (אריזה), שם בונים ומריצים הכי הרבה.
5. **מ4 — אישיים:** העברת `git-band` ו‑`hebrew-rules`, ובניית `israel-time`.

לכל mod: `claude plugin validate`, בדיקות ב‑`claude plugin test`, ובדיקת טיפוסים.
`tools/mods/` נכנס לשער של המאגר.

ד2 (שירותי Rust) ממתין עד שתחליט אם מ0–מ1 קודמים לו. ההמלצה: כן — הם קצרים, ו‑ד2
הוא בדיוק עבודה עם בנייה ברקע, שבה `lm-guard` היה מונע את התקלה של ד1.
