# אפליקציית דסקטופ בקוד פתוח — אפיון ותוכנית

המערכת עוברת מ״פרויקט שמריצים מהטרמינל״ למוצר: מורידים קובץ התקנה מ‑GitHub,
מתקינים, פותחים ועובדים. בלי Node, בלי טרמינל, בלי `.env.local`. הקוד פתוח לכולם,
והנתונים של כל משתמש נשארים על המחשב שלו.

- **עודכן:** 12.10.2026
- **מצב:** טיוטה — מחכה להחלטות ד1–ד10 למטה
- **משפיע על:** ספרינט 1 (Firebase) ב‑[SPRINTS.md](SPRINTS.md) מוקפא עד החלטה ד2

---

## 1. המטרה

**מוכן כאשר** — על מחשב Windows נקי, בלי Node ובלי כלי פיתוח:

1. מורידים `Setup.exe` מעמוד ה‑Releases במאגר
2. מתקינים בלי הרשאות מנהל
3. בפתיחה הראשונה עונים על שתי שאלות (שם, להתחיל ריק או עם דוגמה) ומגיעים למסך ״היום״
4. מוסיפים משימה עם תזכורת — ההתראה קופצת בזמן, גם כשהחלון ממוזער למגש
5. סוגרים ופותחים מחדש — הכול נשאר
6. יוצאת גרסה חדשה — האפליקציה מציעה לעדכן, מעדכנת, והנתונים נשארים

## 2. מה משתנה ומה לא

## 3. עקרונות

1. **מקומי קודם.** אין חשבון, אין שרת חיצוני, אין טלמטריה. רשת רק לגוגל יומן,
   ל‑Claude (אם הוזן מפתח) ולבדיקת עדכונים.
2. **אפס נתונים אישיים במאגר.** לא שמות, לא טלפונים, לא סודות. הכול נכנס דרך
   ההגדרות בזמן ריצה.
3. **קוד אחד.** כל שינוי עובד גם בדפדפן וגם בדסקטופ. מה שייחודי לדסקטופ יושב
   בתיקייה `desktop/` ובגשר צר אחד.
4. **מופע אחד.** פתיחה שנייה מביאה לקדמה את החלון הקיים.
5. **לא לאבד נתונים.** גיבוי לפני כל מיגרציה ולפני כל עדכון; הסרת התקנה לא
   מוחקת את תיקיית הנתונים בלי לשאול.

```

│   ├─ נעילת מופע יחיד, מגש, עדכונים       │

│        │  preload: גשר צר (IPC)       │ │
│        ▼                              ▼ │
│   המסכים הקיימים  ◄── HTTP ──►  .next/standalone/server.js
│                    127.0.0.1 בלבד       │   ├─ נתיבי /api הקיימים
│                    + אסימון לכל הפעלה   │   └─ node:sqlite → userData/data/lior.db
```

### 5.1 למה Electron

- **השרת נשאר כמו שהוא.** Electron מצרף Node משלו. לפי
  [electron/electron#45532](https://github.com/electron/electron/issues/45532),
  `node:sqlite` עובד בלי דגל כבר מ‑Electron 35.0.2 (Node 22.14). לפי
  [kewutong#68](https://github.com/raawaa/kewutong/issues/68), Electron 41–44
  מצרפים Node 24. אין מודולים בינאריים לבנות מחדש — זה היתרון הגדול של
  `node:sqlite` על פני `better-sqlite3`.
- **Tauri** קטן בהרבה, אבל השרת שלנו הוא Node. היינו צריכים לצרף Node כ‑sidecar
  (ואז הגודל דומה) או לכתוב את שכבת הנתונים מחדש ב‑Rust.
- **PWA בלבד** כבר קיים, אבל עדיין דורש שמישהו יריץ שרת. הוא לא ״מתקינים ועובד״.

המחיר: קובץ התקנה גדול (הערכה: סביב 100MB, נמדד בספייק) וזיכרון של Chromium.

### 5.2 השרת בתוך האפליקציה

- `next.config.ts` מקבל `output: "standalone"`. אחרי `next build` מעתיקים
  `public` ו‑`.next/static` לתוך `.next/standalone` (כך כתוב ב‑
  `node_modules/next/dist/docs/01-app/03-api-reference/05-config/01-next-config-js/output.md`).
- התהליך הראשי מפעיל את `server.js` עם `HOSTNAME=127.0.0.1` ופורט פנוי, ומחכה
  שיענה לפני שהחלון נפתח (מסך פתיחה קצר בינתיים).
- **נתיב המסד:** `LIOR_DB_PATH` כבר קיים ב‑`src/lib/db.ts:23` ומקבל את
  `app.getPath("userData")/data/lior.db`. הגיבויים כבר נשמרים ליד הקובץ
  (`src/lib/db.ts:255`). צריך להוציא את התלות ב‑`process.cwd()` שבשורה 19.
- הדגל `--experimental-sqlite` לא נחוץ בתוך Electron. בסקריפטים של הפיתוח הוא
  נשאר כל עוד Node המקומי הוא 22.12.

### 5.3 כתובת קבועה (מקור)

`localStorage` שמור לפי מקור — כולל הפורט. אם הפורט משתנה בכל הפעלה, נאבדים
ההעדפות של המכשיר, מצב סרגל הצד, ו**רשימת התזכורות שכבר הוצגו**
(`src/lib/device-prefs.ts`) — כלומר תזכורות יקפצו שוב.

- **מועדף:** סכמה פנימית (`protocol.handle`) שמעבירה בקשות לשרת המקומי. המקור
  קבוע, ואין פורט שנראה החוצה.
- **חלופה:** פורט שנבחר בהפעלה הראשונה ונשמר בקובץ הגדרות של האפליקציה.

ההכרעה — בספייק (ספרינט ד0).

### 5.4 אבטחה

שרת על `127.0.0.1` חשוף לכל תוכנה במחשב, **וגם לכל אתר שפתוח בדפדפן**: אתר זדוני
יכול לשלוח `fetch` ל‑`localhost` ולנסות לקרוא או למחוק נתונים.

- **אסימון לכל הפעלה.** התהליך הראשי מייצר מחרוזת אקראית, מעביר אותה לשרת
  במשתנה סביבה, ומוסיף אותה לכל בקשה של החלון. `src/proxy.ts` (ב‑Next 16
  `middleware` נקרא `proxy`) דוחה כל בקשה בלי האסימון, כשרצים במצב דסקטופ.
- **החלון:** `contextIsolation`, `sandbox`, בלי `nodeIntegration`. ה‑preload
  חושף רק פונקציות מוגדרות (ראה 5.6).
- **קישורים חיצוניים** (אתר חברת החשמל, קישור ב‑הערה) נפתחים בדפדפן הרגיל דרך
  `shell.openExternal`, ורק `http`/`https`. ניווט של החלון מחוץ לאפליקציה נחסם.
- **Service worker** כבוי בדסקטופ (`src/components/pwa.tsx:57`) — אין בו צורך,
  והוא עלול להגיש גרסה ישנה אחרי עדכון. ב‑PWA בדפדפן הוא נשאר.

### 5.5 סודות

כתובות ה‑iCal ומפתח Claude עוברים מ‑`.env.local` ל‑**הגדרות › חיבורים**:

- מוזנים במסך, נשלחים דרך הגשר לתהליך הראשי, ונשמרים מוצפנים ב‑`safeStorage`
  (ב‑Windows — DPAPI, קשור למשתמש במחשב).
- השרת מקבל אותם במשתני סביבה בהפעלה. שינוי מפעיל מחדש את השרת בשקט.
- סדר עדיפויות: הגדרות → משתני סביבה. כך מצב הפיתוח עם `.env.local` ממשיך לעבוד.
- הערך לא חוזר לממשק אחרי שמירה — רק ״מוגדר / לא מוגדר״ וכפתור ״החלף״.

### 5.6 הגשר (preload)

רק מה שהדפדפן לא יכול לעשות בעצמו:

| פונקציה | מה עושה |
|---|---|
| `appInfo()` | גרסה, פלטפורמה, האם במצב דסקטופ |
| `openDataFolder()` | פותח את תיקיית הנתונים בסייר הקבצים |
| `chooseBackupFolder()` | בחירת תיקייה לגיבוי נוסף (למשל OneDrive) |
| `setSecret(key, value)` / `secretStatus()` | שמירת סוד, ובדיקה אם מוגדר |
| `setAutoStart(on)` | הפעלה עם עליית Windows |
| `checkForUpdates()` | בדיקה ידנית מתוך ״הגדרות › אודות״ |

## 6. מה המשתמש רואה

### 6.1 פתיחה ראשונה

1. ״איך לקרוא לך?״ — מחליף את ״ליאור״ הקבוע ב‑`src/app/page.tsx:135`
2. ״להתחיל ריק או עם נתוני דוגמה?״ — הדוגמה מוחקת את עצמה בלחיצה אחת
3. ״יש לך גיבוי?״ — ייבוא JSON (קיים בהגדרות › גיבוי) או קובץ `lior.db`

### 6.2 מעטפת

- **מגש:** סגירת החלון ממזערת למגש (ניתן לכבות). תפריט: פתח, הוספה מהירה, יציאה
- **הפעלה עם המחשב** — כבוי כברירת מחדל, מתג בהגדרות
- **התראות** דרך מנגנון ההתראות של Windows, כולל שם ואייקון האפליקציה
- **קיצור גלובלי** להוספה מהירה מכל מקום (רשות, ניתן לשינוי)
- **זיכרון חלון:** גודל, מיקום, ומסך אחרון
- **הגדרות › אודות:** גרסה, קישור למאגר, בדיקת עדכונים, פתיחת תיקיית הנתונים

### 6.3 עדכונים

- בדיקה בהפעלה ופעם ביום מול GitHub Releases (`electron-updater`)
- ״יש גרסה חדשה — לעדכן עכשיו או ביציאה?״. לא מעדכנים בלי לשאול
- לפני הפעלה ראשונה של גרסה חדשה: גיבוי של המסד, ואז המיגרציות

- ☐ מדידה: גודל קובץ ההתקנה, זמן עד שהחלון מוכן, זיכרון

**מוכן כאשר:** אפליקציה לא ארוזה נפתחת, משימה נשמרת ונשארת אחרי הפעלה מחדש.
אם משהו כאן נכשל — עוצרים וחוזרים להחלטה ד1 לפני שממשיכים.

### ד1 — ניתוק מהסביבה · M

- ☐ נתיב מסד וגיבויים מבחוץ, בלי `process.cwd()`
- ☐ סודות מההגדרות עם נפילה ל‑env (5.5)
- ☐ שם המשתמש ושם המוצר מההגדרות; מסך פתיחה ראשונה (6.1)
- ☐ `src/proxy.ts` עם בדיקת אסימון במצב דסקטופ
- ☐ Service worker כבוי בדסקטופ

**מוכן כאשר:** מצב הדפדפן עובד כמו היום, כל הבדיקות ירוקות, ואין בקוד שם פרטי.

### ד2 — מעטפת הדסקטופ · M

- ☐ מופע יחיד, מגש, זיכרון חלון, תפריט
- ☐ התראות של Windows (כולל `AppUserModelId`), הפעלה עם המחשב
- ☐ קישורים חיצוניים לדפדפן, חסימת ניווט
- ☐ גשר: תיקיית נתונים, תיקיית גיבוי נוספת, סודות
- ☐ בדיקת עשן `_electron`

**מוכן כאשר:** תזכורת קופצת כשהחלון במגש; פתיחה שנייה מביאה את הקיים.

### ד3 — אריזה והתקנה · M

- ☐ `electron-builder` עם מתקין NSIS למשתמש הנוכחי (בלי מנהל)
- ☐ אייקונים לכל הגדלים (`scripts/make-icons.mjs` קיים)
- ☐ הסרה שואלת אם למחוק את הנתונים
- ☐ **התקנה אצלך** והעברת `data/lior.db` הנוכחי לתיקיית האפליקציה

**מוכן כאשר:** סעיפים 1–5 של ״מוכן כאשר״ (סעיף 1 כאן) עוברים על המחשב שלך.

### ד4 — קוד פתוח · S–M

- ☐ הקבצים מסעיף 7, צילומי מסך עם נתוני דוגמה
- ☐ GitHub Actions: בדיקות על PR, בנייה ופרסום על תג
- ☐ **פעולה שלך:** שינוי שם המאגר והפיכתו לציבורי

**מוכן כאשר:** Release `v1.0.0` מופיע במאגר הציבורי עם קובץ התקנה שנבנה ב‑CI.

### ד5 — עדכונים · S

- ☐ `electron-updater` מול GitHub Releases, באישור המשתמש
- ☐ גיבוי לפני מיגרציה בגרסה חדשה
- ☐ ״הגדרות › אודות״

**מוכן כאשר:** עדכון מ‑`v1.0.0` ל‑`v1.0.1` עובר אצלך והנתונים נשארים.

### אחר כך

- Linux (AppImage), ואחריו macOS (לפי ד8)
- שפה נוספת לממשק (לפי ד6)
- חתימת קוד (לפי ד9)
- סנכרון רשות לטלפון (לפי ד2) — למשל קובץ מוצפן בתיקיית ענן שהמשתמש בוחר
