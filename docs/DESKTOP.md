# אפליקציית דסקטופ בקוד פתוח — אפיון ותוכנית

המערכת עוברת מ״פרויקט שמריצים מהטרמינל״ למוצר: מורידים קובץ התקנה מ‑GitHub,
מתקינים, פותחים ועובדים. בלי Node, בלי טרמינל, בלי `.env.local`. הקוד פתוח לכולם,
והנתונים של כל משתמש נשארים על המחשב שלו.

- **עודכן:** 12.10.2026
- **מצב:** כל ההחלטות הוכרעו (12.10): ה1 — **Tauri**, ה2–ה10 — כמו ההמלצות. נשאר לבחור את השם עצמו (ה4)
- **משפיע על:** ספרינט 1 (Firebase) ב‑[SPRINTS.md](SPRINTS.md) מוקפא עד החלטה ה2

---

## 1. המטרה

**מוכן כאשר** — על מחשב Windows נקי, בלי Node ובלי כלי פיתוח:

1. מורידים `Setup.exe` מעמוד ה‑Releases במאגר
2. מתקינים בלי הרשאות מנהל
3. בפתיחה הראשונה עונים על שתי שאלות (שם, להתחיל ריק או עם דוגמה) ומגיעים למסך ״היום״
4. מוסיפים משימה עם תזכורת — ההתראה קופצת בזמן, גם כשהחלון ממוזער למגש
5. סוגרים ופותחים מחדש — הכול נשאר
6. יוצאת גרסה חדשה — האפליקציה מציעה לעדכן, מעדכנת, והנתונים נשארים

## 2. מה משתנה ומה לא

| | היום | בדסקטופ |
|---|---|---|
| הפעלה | `npm run dev` בטרמינל | קיצור דרך בתפריט התחל |
| דרישות | Node 22 + `npm install` | כלום. WebView2 מותקן ב‑Windows 10/11, ואם חסר — המתקין מוריד אותו |
| שרת | Next רץ ב‑Node ומגיש `/api` | **אין שרת.** המסכים נבנים מראש לקבצים סטטיים, והנתונים עוברים דרך פקודות Rust |
| מיקום הנתונים | `data/lior.db` בתוך תיקיית הקוד | `%APPDATA%\<מזהה האפליקציה>\lior.db` |
| סודות (iCal, Claude) | `.env.local` | מסך ההגדרות, נשמרים במנהל האישורים של Windows ולא חוזרים לממשק |
| שם וברכה | ״ליאור״ ו‑״Lior Management״ קבועים בקוד | שם המשתמש מההגדרות, שם המוצר לפי ה4 |
| התראות | רק כשלשונית הדפדפן פתוחה | גם מהמגש, והפעלה עם עליית המחשב (רשות) |
| עדכונים | `git pull` | אוטומטי מ‑GitHub Releases, באישור |
| מסכים ולוגיקה | — | **לא משתנים.** אותם רכיבים, אותו `store.ts`, אותן שאילתות ומיגרציות |

מצב הפיתוח בדפדפן (`npm run dev`, עם נתיבי `/api` ו‑`node:sqlite`) נשאר, וכל
בדיקות ה‑Vitest וה‑Playwright ממשיכות לרוץ עליו. Tauri הוא דרך הובלה נוספת
לאותה שכבת נתונים, לא גרסה נפרדת.

## 3. עקרונות

1. **מקומי קודם.** אין חשבון, אין שרת חיצוני, אין טלמטריה. רשת רק לגוגל יומן,
   ל‑Claude (אם הוזן מפתח) ולבדיקת עדכונים.
2. **אפס נתונים אישיים במאגר.** לא שמות, לא טלפונים, לא סודות. הכול נכנס דרך
   ההגדרות בזמן ריצה.
3. **קוד אחד.** הלוגיקה והשאילתות נשארות ב‑TypeScript. Rust עושה רק מה שהדפדפן
   לא יכול: קובץ SQLite, סודות, רשת בלי CORS, מגש, התראות, עדכונים.
4. **מופע אחד.** פתיחה שנייה מביאה לקדמה את החלון הקיים.
5. **לא לאבד נתונים.** גיבוי לפני כל מיגרציה ולפני כל עדכון; הסרת התקנה לא
   מוחקת את הנתונים בלי לשאול.

## 5. ארכיטקטורה

```
┌──────────────────────── Tauri ────────────────────────┐
│  WebView2 (Chromium של Windows)                        │
│   המסכים הקיימים — Next בייצוא סטטי (output: "export")│
│        │                                               │
│   store.ts ──► repo.ts (TypeScript, אסינכרוני)         │
│        │            │                                  │
│        │       מתאם מסד: TauriDb ──invoke──┐           │
│        │                                   ▼           │
│        └─ calendar / assist ──invoke──► src-tauri (Rust)│
│                                       ├─ rusqlite → lior.db
│                                       ├─ סודות → Credential Manager
│                                       ├─ HTTP: גוגל יומן, Claude
│                                       └─ מגש, התראות, עדכונים
└────────────────────────────────────────────────────────┘

מצב דפדפן (פיתוח ובדיקות) — בלי שינוי:
   store.ts ──fetch──► /api/* ──► repo.ts ──► מתאם NodeDb ──► node:sqlite
```

### 5.1 למה Tauri ״אמיתי״ ולא Node בתוך Tauri

היו שתי דרכים לשים את המערכת ב‑Tauri:

| | Node כ‑sidecar | Tauri מקורי (נבחר) |
|---|---|---|
| מה זה | לצרף `node.exe` ולהריץ את שרת Next כמו היום | המסכים כקבצים סטטיים, הנתונים דרך Rust |
| עבודה | קטנה | גדולה יותר: `repo.ts` הופך אסינכרוני, וגוגל יומן ו‑Claude עוברים ל‑Rust |
| גודל | ~40MB ומעלה (Node עצמו) | מגה‑בייטים בודדים |
| שרת על `localhost` | יש — וצריך אסימון נגד אתרים זדוניים | **אין** — אין מה לתקוף |
| מה נשאר מהיתרון של Tauri | מעט: זה Electron בעקיפין | הכול |

אם ספרינט ד0 יגלה חסם בדרך המקורית — ה‑sidecar הוא דרך המילוט.

### 5.2 המסכים — ייצוא סטטי

- כל ששת המסכים כבר `"use client"`, ואין בהם קריאה לשרת חוץ מ‑`/api`. לכן
  `output: "export"` מתאים להם.
- ייצוא סטטי לא תומך ב‑`redirects()` וב‑`headers()` שב‑`next.config.ts`. הבנייה
  ל‑Tauri משתמשת בתצורה נפרדת בלעדיהם; ההפניות הישנות (`/daily`, `/manage`)
  לא נחוצות באפליקציה חדשה.
- הכתובת קבועה (`http://tauri.localhost` ב‑Windows), כך ש‑`localStorage` —
  העדפות המכשיר ורשימת התזכורות שכבר הוצגו (`src/lib/device-prefs.ts`) — נשמר.
- Service worker כבוי ב‑Tauri (`src/components/pwa.tsx:57`); ב‑PWA בדפדפן הוא נשאר.

### 5.3 שכבת הנתונים — הלב של המעבר

היום `repo.ts` (1,165 שורות, 58 פונקציות מיוצאות) קורא ל‑`DatabaseSync` של
`node:sqlite` באופן סינכרוני, ו‑`store.ts` מגיע אליו דרך `fetch` לנתיבי `/api`.

1. **ממשק מסד אחד** (`src/lib/db-adapter.ts`): `all`, `get`, `run`, `exec`,
   `batch` — כולם אסינכרוניים.
2. **שני מתאמים:**
   - `NodeDb` — עוטף את `node:sqlite`. משמש את נתיבי `/api` במצב דפדפן ואת Vitest.
   - `TauriDb` — `invoke` לפקודות Rust מעל `rusqlite` (גרסה עם SQLite מובנה).
3. **`repo.ts` הופך אסינכרוני** — `await` לפני כל שאילתה. השאילתות עצמן לא משתנות.
4. **טרנזקציות:** `repo.ts` פותח `BEGIN`/`COMMIT` בשני מקומות (שורות 174 ו‑1026 —
   סדר ידני וייבוא דף חשבון). ב‑Tauri הן עוברות כ‑`batch` אחד ש‑Rust מריץ
   בטרנזקציה אחת.
5. **`store.ts`** מקבל ״הובלה״: `http` (כמו היום) או `local` (קורא ל‑`repo.ts` ישירות).
   זו הנקודה היחידה שיודעת שיש Tauri — אף מסך לא משתנה.
6. **מיגרציות:** אותו מנגנון `PRAGMA user_version` ב‑`db.ts`, רץ דרך המתאם.
   Rust מגבה את הקובץ לפני שהן רצות.

למה גשר משלנו ולא `tauri-plugin-sql`: הוא רץ על מאגר חיבורים, כך ש‑`BEGIN`
ו‑`COMMIT` בשתי קריאות נפרדות לא מובטחים לאותו חיבור. גשר של ~150 שורות Rust
נותן שליטה מלאה. (לאמת בספייק.)

### 5.4 סודות ורשת — ב‑Rust

הכלל של היום נשמר: **הסוד לא מגיע לקוד של הממשק.**

- כתובות ה‑iCal ומפתח Claude נשמרים במנהל האישורים של Windows (`keyring`).
  הממשק כותב אותם פעם אחת ומקבל בחזרה רק ״מוגדר / לא מוגדר״.
- `calendar_fetch` — Rust קורא את הכתובת מהמנהל, מוריד את ה‑`.ics` (גוגל לא
  מאפשר הורדה ישירה מהדפדפן — CORS), ומחזיר את הטקסט. הפענוח נשאר ב‑`ical.js`,
  כך ש‑`google-calendar.ts` ממשיך לעבוד.
- `assist_parse` — אותו דבר מול `api.anthropic.com`.
- מצב דפדפן: נתיבי `/api/calendar/google` ו‑`/api/assist/parse` עם `.env.local`,
  כמו היום.

### 5.5 אבטחה

- **אין שרת מקומי** — הסיכון של ״אתר זדוני שולח בקשה ל‑localhost״ לא קיים.
- **הרשאות Tauri** (`capabilities`): החלון מקבל רק את הפקודות שלנו ואת התוספים
  שברשימה. בלי גישה כללית לקבצים או לרשת מהממשק.
- **CSP** קשיח: סקריפטים רק מהאפליקציה, `connect-src` רק ל‑IPC של Tauri.
- **קישורים חיצוניים** נפתחים בדפדפן הרגיל (`tauri-plugin-opener`), רק `http`/`https`.
- **גשר SQL** מקבל שאילתות מהממשק — מקובל, כי הממשק הוא הקוד שלנו בלבד ואין
  בו תוכן מרוחק. ה‑CSP הוא מה ששומר על ההנחה הזו.

## 6. מה המשתמש רואה

### 6.1 פתיחה ראשונה

1. ״איך לקרוא לך?״ — מחליף את ״ליאור״ הקבוע ב‑`src/app/page.tsx:135`
2. ״להתחיל ריק או עם נתוני דוגמה?״ — הדוגמה מוחקת את עצמה בלחיצה אחת
3. ״יש לך גיבוי?״ — ייבוא JSON (קיים בהגדרות › גיבוי) או קובץ `lior.db`

### 6.2 מעטפת

- **מגש:** סגירת החלון ממזערת למגש (ניתן לכבות). תפריט: פתח, הוספה מהירה, יציאה
- **הפעלה עם המחשב** — כבוי כברירת מחדל, מתג בהגדרות
- **התראות** של Windows, עם שם ואייקון האפליקציה
- **קיצור גלובלי** להוספה מהירה (רשות, ניתן לשינוי)
- **הגדרות › אודות:** גרסה, קישור למאגר, בדיקת עדכונים, פתיחת תיקיית הנתונים

### 6.3 עדכונים

- בדיקה בהפעלה ופעם ביום מול GitHub Releases
- ״יש גרסה חדשה — לעדכן עכשיו או ביציאה?״. לא מעדכנים בלי לשאול
- כל עדכון חתום במפתח של הפרויקט (חובה ב‑Tauri). המפתח הפרטי נשמר אצלך ובסודות
  של GitHub, אף פעם לא במאגר
- לפני הפעלה ראשונה של גרסה חדשה: גיבוי של המסד, ואז המיגרציות

- **הקיימות לא משתנות:** 180 בדיקות Vitest ו‑55 Playwright רצות במצב דפדפן.
  בדיקות `repo.ts` עוברות לגרסה האסינכרונית מול `NodeDb`.
- **חדש — אותן בדיקות על שני המתאמים:** בדיקת חוזה אחת שרצה על `NodeDb` ועל
  מתאם שמדמה את `TauriDb`, כדי ששני הצדדים יחזירו אותו דבר.
- **חדש — Rust:** `cargo test` לגשר (שאילתה, טרנזקציה שנכשלת באמצע ומתגלגלת
  אחורה, גיבוי לפני מיגרציה).
- **חדש — עשן דסקטופ:** `tauri-driver` מול האפליקציה הבנויה: פותח, מוסיף משימה,
  סוגר, פותח שוב, המשימה שם.
- **ידני לפני כל גרסה:** התקנה על משתמש Windows נקי (או מכונה וירטואלית),
  עדכון מהגרסה הקודמת, הסרה.

### ד0 — ספייק · S

- ☐ `src-tauri` עם חלון שטוען את הייצוא הסטטי של המסכים
- ☐ גשר `rusqlite`: `all`/`get`/`run`/`batch`, והמיגרציות הקיימות רצות דרכו
- ☐ ישות אחת מקצה לקצה (משימות): הוספה, סימון, מחיקה, אחרי הפעלה מחדש
- ☐ מדידה: גודל המתקין, זמן עד שהחלון מוכן, זיכרון

**מוכן כאשר:** משימה נשמרת באפליקציית Tauri ונשארת אחרי הפעלה מחדש. אם משהו
נכשל — עוצרים ובוחנים את דרך ה‑sidecar (5.1) לפני שממשיכים.

### ד1 — שכבת נתונים אסינכרונית · L

- ☐ `db-adapter.ts` עם `NodeDb` ו‑`TauriDb`
- ☐ `repo.ts` אסינכרוני, טרנזקציות כ‑`batch`
- ☐ נתיבי `/api` עוברים ל‑`await` — מצב הדפדפן עובד כמו היום
- ☐ `store.ts` עם הובלה `http` / `local`
- ☐ תצורת בנייה נפרדת לייצוא סטטי
- ☐ בדיקת חוזה על שני המתאמים

**מוכן כאשר:** כל 180 בדיקות Vitest ו‑55 Playwright ירוקות, וכל המסכים עובדים
באפליקציית Tauri.

### ד2 — שירותי Rust וניתוק מהסביבה · M

- ☐ סודות ב‑`keyring`; `calendar_fetch` ו‑`assist_parse`
- ☐ גיבוי יומי ולפני מיגרציה ב‑Rust (14 אחרונים, כמו היום)
- ☐ שם המשתמש ושם המוצר מההגדרות; מסך פתיחה ראשונה (6.1)
- ☐ Service worker כבוי ב‑Tauri

**מוכן כאשר:** גוגל יומן ו‑Claude עובדים באפליקציה, ואין בקוד שם פרטי.

### ד3 — מעטפת הדסקטופ · M

- ☐ מופע יחיד, מגש, זיכרון חלון
- ☐ התראות של Windows, הפעלה עם המחשב
- ☐ קישורים חיצוניים, CSP, הרשאות Tauri מצומצמות
- ☐ תיקיית נתונים, תיקיית גיבוי נוספת

**מוכן כאשר:** תזכורת קופצת כשהחלון במגש; פתיחה שנייה מביאה את הקיים.

### ד4 — אריזה והתקנה · M

**מוכן כאשר:** סעיפים 1–5 של ״מוכן כאשר״ (סעיף 1 כאן) עוברים על המחשב שלך.
