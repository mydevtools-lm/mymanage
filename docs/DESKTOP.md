# אפליקציית דסקטופ בקוד פתוח — אפיון ותוכנית

המערכת עוברת מ״פרויקט שמריצים מהטרמינל״ למוצר: מורידים קובץ התקנה מ‑GitHub,
מתקינים, פותחים ועובדים. בלי Node, בלי טרמינל, בלי `.env.local`. הקוד פתוח לכולם,
והנתונים של כל משתמש נשארים על המחשב שלו.

- **עודכן:** 12.10.2026
- **מצב:** כל ההחלטות הוכרעו: ה1 — **Tauri** (12.10), ה2–ה10 — כמו ההמלצות (12.10), והשם (ה4) — **mymanage** (15.10)
- **משפיע על:** ספרינט 1 (Firebase) ב‑[SPRINTS.md](SPRINTS.md) מוקפא עד החלטה ה2

---

## 1. המטרה

**מוכן כאשר** — על מחשב Windows נקי, בלי Node ובלי כלי פיתוח:

1. מורידים `Setup.exe` מעמוד ה‑Releases במאגר
2. מתקינים בלי הרשאות מנהל
3. בפתיחה הראשונה עונים על שתי שאלות (שם, להתחיל ריק או עם דוגמה) ומגיעים למסך ״היום״
4. מוסיפים משימה עם תזכורת — ההתראה קופצת בזמן, גם כשהחלון ממוזער למגש
5. סוגרים ופותחים מחדש — הכול נשאר
6. יוצאת גרסה חדשה — האפליקציה מציעה לעדכן, מעדכנת, והנתונים נשארים

## 2. מה משתנה ומה לא

| | היום | בדסקטופ |
|---|---|---|
| הפעלה | `npm run dev` בטרמינל | קיצור דרך בתפריט התחל |
| דרישות | Node 22 + `npm install` | כלום. WebView2 מותקן ב‑Windows 10/11, ואם חסר — המתקין מוריד אותו |
| שרת | Next רץ ב‑Node ומגיש `/api` | **אין שרת.** המסכים נבנים מראש לקבצים סטטיים, והנתונים עוברים דרך פקודות Rust |
| מיקום הנתונים | `data/lior.db` בתוך תיקיית הקוד | `%APPDATA%\<מזהה האפליקציה>\data.db` |

| שם וברכה | ״ליאור״ ו‑״Lior Management״ קבועים בקוד | שם המשתמש מההגדרות, שם המוצר לפי ה4 |

לאותה שכבת נתונים, לא גרסה נפרדת.

## 3. עקרונות

1. **מקומי קודם.** אין חשבון, אין שרת חיצוני, אין טלמטריה. רשת רק לגוגל יומן,
   ל‑Claude (אם הוזן מפתח) ולבדיקת עדכונים.
2. **אפס נתונים אישיים במאגר.** לא שמות, לא טלפונים, לא סודות. הכול נכנס דרך
   ההגדרות בזמן ריצה.
3. **קוד אחד.** הלוגיקה והשאילתות נשארות ב‑TypeScript. Rust עושה רק מה שהדפדפן
   לא יכול: קובץ SQLite, סודות, רשת בלי CORS, מגש, התראות, עדכונים.
4. **מופע אחד.** פתיחה שנייה מביאה לקדמה את החלון הקיים.
5. **לא לאבד נתונים.** גיבוי לפני כל מיגרציה ולפני כל עדכון; הסרת התקנה לא
   מוחקת את הנתונים בלי לשאול.

## 5. ארכיטקטורה

```
┌──────────────────────── Tauri ────────────────────────┐
│  WebView2 (Chromium של Windows)                        │
│   המסכים הקיימים — Next בייצוא סטטי (output: "export")│
│        │                                               │
│   store.ts ──► repo.ts (TypeScript, אסינכרוני)         │
│        │            │                                  │
│        │       מתאם מסד: TauriDb ──invoke──┐           │
│        │                                   ▼           │
│        └─ calendar / assist ──invoke──► src-tauri (Rust)│
│                                       ├─ rusqlite → lior.db
│                                       ├─ סודות → secrets.json (DPAPI)
│                                       ├─ HTTP: גוגל יומן, Claude
│                                       └─ מגש, התראות, עדכונים
└────────────────────────────────────────────────────────┘

מצב דפדפן (פיתוח ובדיקות) — בלי שינוי:
   store.ts ──fetch──► /api/* ──► repo.ts ──► מתאם NodeDb ──► node:sqlite
```

### 5.1 למה Tauri ״אמיתי״ ולא Node בתוך Tauri

היו שתי דרכים לשים את המערכת ב‑Tauri:

| | Node כ‑sidecar | Tauri מקורי (נבחר) |
|---|---|---|
| מה זה | לצרף `node.exe` ולהריץ את שרת Next כמו היום | המסכים כקבצים סטטיים, הנתונים דרך Rust |
| עבודה | קטנה | גדולה יותר: `repo.ts` הופך אסינכרוני, וגוגל יומן ו‑Claude עוברים ל‑Rust |
| גודל | ~40MB ומעלה (Node עצמו) | מגה‑בייטים בודדים |
| שרת על `localhost` | יש — וצריך אסימון נגד אתרים זדוניים | **אין** — אין מה לתקוף |
| מה נשאר מהיתרון של Tauri | מעט: זה Electron בעקיפין | הכול |

אם ספרינט ד0 יגלה חסם בדרך המקורית — ה‑sidecar הוא דרך המילוט.

### 5.2 המסכים — ייצוא סטטי

- כל ששת המסכים כבר `"use client"`, ואין בהם קריאה לשרת חוץ מ‑`/api`. לכן
  `output: "export"` מתאים להם.
- ייצוא סטטי לא תומך ב‑`redirects()` וב‑`headers()` שב‑`next.config.ts`. הבנייה
  ל‑Tauri משתמשת בתצורה נפרדת בלעדיהם; ההפניות הישנות (`/daily`, `/manage`)
  לא נחוצות באפליקציה חדשה.
- הכתובת קבועה (`http://tauri.localhost` ב‑Windows), כך ש‑`localStorage` —
  העדפות המכשיר ורשימת התזכורות שכבר הוצגו (`src/lib/device-prefs.ts`) — נשמר.
- Service worker כבוי ב‑Tauri (`src/components/pwa.tsx:57`); ב‑PWA בדפדפן הוא נשאר.

### 5.3 שכבת הנתונים — הלב של המעבר

לפני ד1 `repo.ts` קרא ל‑`DatabaseSync` של `node:sqlite` באופן סינכרוני, וכל נתיב
`/api` החזיק בעצמו את בדיקות הקלט שלו. אחרי ד1:

```
store.ts ─ api() ─┬─ דפדפן: fetch → route.ts (שורה אחת) → api-next.ts ─┐
                  └─ Tauri: local-api.ts ──────────────────────────────┤
                                                                       ▼
                                   api-routes.ts — כל נתיבי הנתונים, פעם אחת
                                                                       ▼
                         repo.ts (אסינכרוני) → db() ─┬─ node-db.ts  → node:sqlite
                                                     └─ tauri-db.ts → Rust
```

1. **ממשק מסד אחד** (`src/lib/db-adapter.ts`): `all`, `get`, `run`, `batch`. מי
   שמריץ את `repo.ts` קובע את המסד הפעיל ב‑`setRepoDb()`.
2. **שני מתאמים:** `node-db.ts` (השרת ו‑Vitest) ו‑`tauri-db.ts` (הגשר ל‑Rust).
3. **`repo.ts` אסינכרוני** — השאילתות עצמן לא השתנו.
4. **אין טרנזקציה פתוחה בין קריאות.** ב‑Tauri כל קריאה חוצה ל‑Rust, ו‑`BEGIN`
   שנשאר פתוח היה בולע כל כתיבה אחרת שהמסך שולח באמצע. במקום זה כתיבות שחייבות
   לנחות יחד — ייבוא JSON, ייבוא דף חשבון, סדר ידני, פריטי רשימה — נאספות קודם
   ונשלחות כ‑`batch` אחד. כל הכנסה נבנית בפונקציית `…Insert`, כך שיצירה בודדת
   וייבוא שלם כותבים שורות באותה דרך.
5. **נתב משותף** (`src/lib/api-routes.ts`): בדיקות הקלט והתשובות של כל נתיבי
   הנתונים כתובות פעם אחת. קובצי `route.ts` הפכו לשורה אחת, ובתוך Tauri אותו נתב
   רץ בלי שרת. זה שונה מהתוכנית המקורית (״הובלה `local` שקוראת ל‑`repo.ts`
   ישירות״) — כך אין שתי גרסאות של אותם כללים.
6. **מיגרציות:** `schema.ts` משותף; `db.ts` מריץ אותן בשרת ו‑`openLocalDb()` ב‑Tauri.
7. **גוגל יומן והוספה במשפט** נשארים בשרת עד ד2, כי הם צריכים סוד. בתוך Tauri
   בינתיים: היומן מוצג ״לא מחובר״, והוספה במשפט עובדת עם הקריאה המקומית.

למה גשר משלנו ולא `tauri-plugin-sql`: הוא רץ על מאגר חיבורים, כך ש‑`BEGIN`
ו‑`COMMIT` בשתי קריאות נפרדות לא מובטחים לאותו חיבור. הגשר שלנו מחזיק חיבור אחד,
ו‑`batch` רץ בטרנזקציה אחת (נבדק ב‑`cargo test`).

### 5.4 סודות ורשת — ב‑Rust

הכלל של היום נשמר: **הסוד לא מגיע לקוד של הממשק.**

- כתובות ה‑iCal ומפתח Claude נשמרים ב‑`secrets.json` בתיקיית האפליקציה, כל ערך
  מוצפן ב‑DPAPI של Windows (`src-tauri/src/vault.rs`) — רק המשתמש הזה במחשב הזה
  יכול לפענח. התוכנית הייתה מנהל האישורים (`keyring`), אבל ב‑ד2 התברר שכשהוא
  מלא (720 רשומות במחשב שלך) Windows דוחה כל רשומה חדשה מעל כמה מאות בתים
  בשגיאה 8, וכתובת יומן לא נכנסת.
  הממשק כותב אותם פעם אחת ומקבל בחזרה רק ״מוגדר / לא מוגדר״.
- `calendar_fetch` — Rust קורא את הכתובת מהמנהל, מוריד את ה‑`.ics` (גוגל לא
  מאפשר הורדה ישירה מהדפדפן — CORS), ומחזיר את הטקסט. הפענוח נשאר ב‑`ical.js`,
  כך ש‑`google-calendar.ts` ממשיך לעבוד.
- `assist_parse` — אותו דבר מול `api.anthropic.com`.
- מצב דפדפן: נתיבי `/api/calendar/google` ו‑`/api/assist/parse` עם `.env.local`,
  כמו היום.

### 5.5 אבטחה

- **אין שרת מקומי** — הסיכון של ״אתר זדוני שולח בקשה ל‑localhost״ לא קיים.
- **הרשאות Tauri** (`src-tauri/capabilities/default.json`): החלון מקבל את הפקודות
  שלנו, ומהתוספים רק האזנה לאירועים (מהמגש), הפעלה עם המחשב ובחירת תיקייה.
  התראות, קישורים ופתיחת תיקיית הנתונים עוברים דרך פקודות שלנו ב‑`shell.rs`,
  שבודקות מה הן מקבלות — לדף אין הרשאות התראות או opener משלו. בלי גישה כללית
  לקבצים או לרשת מהממשק.
- **CSP** קשיח (`tauri.conf.json`): סקריפטים רק מהאפליקציה (Tauri מוסיף את
  ה‑hash של הסקריפטים שבתוך ה‑HTML), `connect-src` לאפליקציה עצמה ול‑IPC,
  בלי מסגרות, בלי שליחת טפסים.
- **קישורים חיצוניים** נפתחים בדפדפן הרגיל דרך `shell_open_url`, רק `http`/`https`.
- **גשר SQL** מקבל שאילתות מהממשק — מקובל, כי הממשק הוא הקוד שלנו בלבד ואין
  בו תוכן מרוחק. ה‑CSP הוא מה ששומר על ההנחה הזו.

### 6.1 פתיחה ראשונה

### ד8 — סנכרון בין מחשבים דרך תיקייה · M–L ☑ הושלם (26.10) — בדיקה בין שני מחשבים אמיתיים מחכה לך

(`mymanage-sync/v1/<מחשב>/seg-…json`, עם סכום בדיקה, נכתבים בשם זמני ומקבלים שם רק כשהם
שלמים — בצד של Rust, `sync.rs`, שמגביל את הנתיבים לתוך התיקייה שנבחרה) וממזג את הקבצים
של האחרים.

- ☑ מודל הנתונים: חותמת לכל שדה, מחיקות נרשמות (״שורה חיה״/״נמחקה״), מזהה לכל מחשב. במקום עמודות זמן חדשות — טבלת חותמות נפרדת

- ☑ תיקיית הסנכרון: הגדרות › סנכרון (במחשב בלבד) — בחירת תיקייה, סנכרון עכשיו, הפסקה. סבב אוטומטי חמש שניות אחרי הפתיחה, כל שתי דקות, ובכל פעם שהחלון נעלם או חוזר
- ☑ מיזוג: שינויים בשדות שונים נשמרים שניהם; באותו שדה מנצח המאוחר; מחיקה מנצחת עריכה, ושורה שנוצרה שוב (ביטול מחיקה) חוזרת; שינוי שמחכה לשורה שעוד לא הגיעה ממתין ולא הולך לאיבוד; שינוי שהמסד דוחה לא עוצר את האחרים
- ☑ מכשיר שני: הצטרפות לתיקייה קיימת ממזגת ולא דורסת; גיבוי של המסד לפני המיזוג הראשון; אותה קטגוריה שנוצרה בשני מחשבים (ברירות המחדל) הופכת לאחת, והמשימות והתקציבים הולכים אחריה
- ☑ דחיסה: אחרי 20 קבצים נכתבת תמונת מצב של המחשב והקבצים הישנים נמחקים; מחשב שהיה כבוי שבוע מתעדכן ממנה
- ☑ בדיקות: 29 בדיקות מנוע עם כמה מחשבים בתיקייה אחת (עריכות במקביל, שעונים שונים, קובץ חלקי או פגום, קובץ חסר באמצע, מחיקה מול עריכה, ביטול מחיקה, רשימות עם פריטים, קטגוריות, תקציבים, החזרת גיבוי, דחיסה, מכשיר כבוי שבוע) + בדיקות Rust לנתיבים וכתיבה שלמה + שלב ״sync״ בבדיקת העשן: האפליקציה האמיתית מול מחשב שני בתהליך נפרד

**לא מסונכרן:** הסודות (כתובות היומן ומפתח Claude) — מוצפנים למשתמש Windows של כל
מחשב, ומוזנים בכל מחשב בנפרד. וגם העדפות של מכשיר (מגש, הפעלה עם המחשב, השפה).
